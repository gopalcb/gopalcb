## A little about me

I enjoy turning ambitious, slightly messy ideas into systems that feel clear, dependable, and easy to explore. These days, I’m especially interested in **API design and development**, **agent runtimes and memory**, **human-in-the-loop workflows**, and **observable cloud platforms**. I care about the parts behind the demo too: strong contracts, safe execution boundaries, useful logs, honest failure states, and documentation that helps to understand *why* the system works.

## What I’m building

| Project | What it explores |
| --- | --- |
| [MCP server for sharing markdown files across agents and chats](https://github.com/gopalcb/markdown-file-sharing-network-across-agents) | A custom MCP server running on AWS Lambda and exposed via an API Gateway endpoint gated behind OAuth2. It can stream cross tools and agents markdown content to a central S3 bucket, organizing documents and access. The MCP plugin integrates with Codex, ChatGPT and Claude across mobile and web interfaces, making shared content easy for people and coding agents to search and access as ready-to-use context for agent tasks. |
| [API Builder Agent](https://github.com/gopalcb/api-builder-agent) | An entity-driven and event-driven Flask and Angular workbench with LangGraph, LangChain Deep Agents and Codex-powered API builder. The agent enables faster and structured way of building REST APIs, enabling quick integration of identity, authentication, OpenTelemetry, endpoint & routing config, caching and other advance tools like embeddings and semantic search. |
| [Deep Agent Hybrid Harness with Codex](https://github.com/gopalcb/deep-agent-harness-with-codex) | A tiny deep-agents harness living alongside Codex and kicks in when my Codex is running out of tokens. Compatible with AWS Bedrock and local models |
| [Custom Agent Runtime](https://github.com/gopalcb/custom-tools-and-runtime-for-agent-work) | A compact runtime with YAML workflows, durable messaging, memory and custom tools. It uses Playwright to let users generate prompt visually and preciously targeting specific UI elements and coding agent can directly jump in and implement. It significantly reduces token consumption and other overhead. |
| [OpenTelemetry Lab](https://github.com/gopalcb/opentelemetry-lab-gb) | An observability blueprint using OpenTelemetry, Tempo, Loki, Elasticsearch, and Kibana. |
